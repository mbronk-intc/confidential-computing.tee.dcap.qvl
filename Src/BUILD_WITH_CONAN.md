# Building with Conan

This project uses Conan 2.x for dependency management. The following dependencies are managed by Conan:
- OpenSSL 3.0.12
- GTest 1.14.0
- spdlog 1.14.1
- fmt 10.2.1

## Prerequisites

1. Install Conan 2.x:
   ```bash
   pip install "conan>=2.0"
   ```

2. Verify Conan installation:
   ```bash
   conan --version
   ```

## Building the Project

### Using CMake Presets (Recommended)

The project includes CMake Presets for easier building with IDE integration:

```bash
# Step 1: Install dependencies
conan install . --output-folder=cmake-build-release --build=missing -s build_type=Release

# Step 2: Configure using preset
cmake --preset release

# Step 3: Build using preset
cmake --build --preset release

# Step 4 (Optional): Run tests
ctest --preset release
```

Available presets:
- `release` - Optimized release build with tests and app enabled
- `debug` - Debug build with tests and app enabled
- `default` - Basic configuration inheriting from Conan defaults

**Benefits of CMake Presets:**
- Automatic inclusion of Conan toolchain
- No need to manually specify `-DCMAKE_TOOLCHAIN_FILE`
- IDE support (VS Code, CLion, Visual Studio)
- Consistent build configuration across team

### Manual Build Steps

If you prefer manual commands or need custom configuration:

#### Step 1: Install Dependencies with Conan

From the `Src` directory, run:

```bash
cd Src
conan install . --output-folder=cmake-build-release --build=missing -s build_type=Release
```

This will:
- Download and build all required dependencies
- Generate CMake configuration files in the `cmake-build-release` directory
- Generate `ConanPresets.json` which is included by `CMakePresets.json`
- Configure OpenSSL to build without tests

#### Step 2: Configure CMake

```bash
cd cmake-build-release
cmake .. -DCMAKE_TOOLCHAIN_FILE=conan_toolchain.cmake -DCMAKE_BUILD_TYPE=Release
```

The `conan_toolchain.cmake` file is automatically generated by Conan and contains all the necessary paths and configuration for the dependencies.

#### Step 3: Build

```bash
cmake --build .
```

Or use make:
```bash
make -j$(nproc)
```


1. Open the folder containing `CMakeLists.txt`

## Customizing Dependencies

Dependencies are managed in the `conanfile.py` file. This provides greater flexibility than the basic `conanfile.txt` format.

### Key Features of conanfile.py

**1. Conditional dependencies:**
```python
def requirements(self):
    self.requires("openssl/3.0.12")
    self.requires("spdlog/1.14.1")
    self.requires("fmt/10.2.1")
    
    if self.options.build_tests:
        self.requires("gtest/1.14.0")  # Only when tests are enabled
```

**2. Configurable build options:**
```bash
# Build with tests enabled
conan install . --output-folder=cmake-build-release -o build_tests=True

# Build with documentation
conan install . --output-folder=cmake-build-release -o build_docs=True
```

**3. Platform-specific configuration:**
The conanfile.py automatically configures dependencies based on the target platform (e.g., forcing static libraries for Emscripten/WASM builds).

### Changing Dependency Versions

Edit `conanfile.py` and modify the version numbers:
```python
def requirements(self):
    self.requires("openssl/3.0.15")  # Updated version
    self.requires("spdlog/1.15.0")   # Updated version
```

### Default Options

All dependencies use static libraries by default:
- `openssl/*:shared=False` and `openssl/*:no_tests=True` (prevents OpenSSL tests from building)
- `gtest/*:shared=False`
- `spdlog/*:shared=False`
- `fmt/*:shared=False`

## Dependency Lockfile

The project includes a `conan.lock` file that locks dependency versions for reproducible builds. This ensures all developers and CI systems use the exact same dependency versions.

### Using the Lockfile

When building, Conan automatically uses the lockfile if present:

```bash
# Install dependencies using lockfile
conan install . --output-folder=cmake-build-release --lockfile=conan.lock
```

### Updating the Lockfile

To update dependencies to newer versions:

```bash
# Update lockfile with latest compatible versions
conan lock create . --lockfile-out=conan.lock --lockfile-overwrite --build=missing -s build_type=Release

# Or update specific package
conan lock create . --lockfile-out=conan.lock --lockfile-overwrite --update=openssl/3.0.15
```

### Why Use a Lockfile?

- **Reproducibility**: Everyone gets identical dependency versions
- **CI/CD stability**: Build pipeline uses consistent dependencies
- **Explicit updates**: Dependency changes are tracked in version control
- **Security**: Prevents unexpected dependency changes

## Advantages over Hunter

1. **No test compilation**: OpenSSL's `no_tests=True` option prevents unnecessary test compilation
2. **Faster builds**: Conan caches binaries across projects
3. **Better control**: Easy to pin exact versions and configure build options
4. **More packages**: Conan has a larger ecosystem of prebuilt packages
5. **Better tooling**: Conan provides better diagnostics and control

## Troubleshooting

### Conan profile not detected
If Conan cannot detect your profile, create one:
```bash
conan profile detect --force
```

### Missing system dependencies
Some packages may require system libraries. Install them using your package manager:
```bash
# Ubuntu/Debian
sudo apt-get install build-essential cmake

# For OpenSSL, you might need:
sudo apt-get install libssl-dev
```

### Clean build
To start fresh:
```bash
rm -rf cmake-build-*
conan remove "*" -c  # Remove Conan cache (optional)
```

## Migration Notes

The following changes were made to migrate from Hunter to Conan:

1. Created `conanfile.py` with project dependencies and flexible configuration
2. Removed `HunterGate` configuration from root `CMakeLists.txt`
3. Added Conan CMake integration (CMAKE_MODULE_PATH and CMAKE_PREFIX_PATH)
4. Replaced all `hunter_add_package()` calls with standard `find_package()` calls
5. Removed Hunter-specific configuration files (kept for reference in `ThirdParty/hunter/`)

All existing `find_package()` calls remain unchanged and work with Conan-provided packages.

### Why conanfile.py instead of conanfile.txt?

The project uses `conanfile.py` for:
- **Conditional dependencies**: GTest is only included when `build_tests=True`
- **Build options**: Control what gets built via Conan options
- **Platform-specific logic**: Automatic configuration for different target platforms
- **Better metadata**: License, author, description for better package management
- **Future extensibility**: Easy to add custom build logic or validation
